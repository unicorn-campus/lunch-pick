# 설계서 ⑤ 지식/도구 — 런치픽(LunchPick)

**작성**: 지식니(지식·데이터 엔지니어) · **작성일** 2026-08-12
**입력**: `_shared/프로젝트정보.md`(`V-04`·`V-06`·`V-07`·`V-11`) · `02-논리아키텍처.md` ·
`03-패턴시퀀스설계.md` · `04-에이전트역할계약서.md` · 기획 산출물 `docs/plan/`
**미검증 설계** — 실제 저장소에 붙여 재 본 값이 아니라 앞 산출물의 이름과 요구 원문에서 펼친 스펙임.
검색 품질(골든셋·원천 오류율·통과율)은 이 문서 소관이 아니며 별도 품질 튜닝에서 다룸.

이 문서는 **"이 담당자는 무엇을 근거로 답하는가"**에 답함.

`R-n`은 담당자(④ 소유) · `S-n`은 내부 저장소(② 소유) · `TB-n`은 Trust Boundary(신뢰 경계, ② 소유) ·
`SL-n`은 Sensitive Label(민감정보 라벨, ② 소유) · `K-n`은 단계 간 전달 집합(③ 소유) ·
`S-Rn`·`S-Bn`·`S-En`은 단계 식별자(③ 소유)임.
`F-n`(민감 필드 ID) · `C-n`(커넥터 번호) · 표·열 · 메타데이터 필터 키 · 변환 지점은 **본 산출물이 소유**함.

**이 문서가 소유하지 않는 값** — 단계 간 전달 집합의 키 이름·State 필드 이름(③) · Mock·실물 구분(②) ·
저장소·도구의 논리 이름과 권한 등급(④) · 타임아웃·재시도(③) · 마스킹 방법의 구현 규칙과 비용 상한(⑥).

#### 정형 접근 경로

④ 역할계약서의 `사용 정보` ⑴ 정형 갈래에 적힌 저장소(`S-1`·`S-3`·`S-5`·`S-6`·`S-7`) 안에서

### 1-2. 비정형정보

#### 경로 채택·미채택

검토한 후보 방식 **4건**을 채택·미채택 모두 적음(표 행 수 = 후보 방식 수 = 4).
갈래 자체는 ④의 `사용 정보`에서 왔고, 그 안에서 무엇을 안 골랐는지는 본 산출물이 정하는 값임.

| 후보 방식 | 채택 | 이유 | 근거 출처 |
|----------|------|------|----------|
| 의미정보(RAG) — 취향 벡터 유사도 검색 인덱스 `S-4` | **채택** | ④가 `R-1`·`R-2`·`R-3`·`R-6`·`R-14`의 `의미 정보(RAG)` 칸에 `S-4`를 적었고, 취향 벡터 ↔ 음식·메뉴 임베딩 유사도 검색이 추천 후보 정렬의 유일한 수단임 | ④ 담당자별 `사용 정보`, `V-07` 3행, ES:05#취향임베딩갱신 |
| 의미정보(RAG) — 문서 코퍼스 검색 | 미채택 | 검색할 문서 코퍼스가 원문에 0건임. 리뷰 텍스트 수집이 `V-09` 4번으로 제외되어 색인할 비정형 원천이 확정 19건 중 LLM 생성 텍스트 1건뿐임 | `V-09` 7번, `V-04` 원천 구성 판정 |
| 관계정보(GraphRAG) | 미채택 | ④의 `관계 정보(GraphRAG)` 칸이 담당자 14명 전원 `0건`이고, ②의 저장 절에 그래프DB가 없음. 다단계 관계 질문이 원문에 0건이며 부정 관계(못 먹는 식재료)는 정형의 `diet_restriction` 표와 `excluded_ingredient_codes` 코드 환산으로 결정론 처리함(ADR-3) | ④ 담당자별 `사용 정보`, `V-09` 7번, ② ADR-3 |
| 용어사전(음식 카테고리·맛 태그) — 덧붙는 층 | **채택** | 카테고리 코드가 화면(달력 색상 태그·Top 5)과 정형 집계·벡터 색인 세 곳에서 같은 낱말로 나와야 하고, 피드백 키워드가 고정 라벨 3종으로 제한되어 1:1 고정이 필요함 | `V-07` 3행, US:UIUX#인사이트, US:UFR-REC-090#입력요구사항 |

**버린 대안 1줄** — 경로마다 남김.

- 정형 접근: **NL2SQL을 버림** — 자연어로 DB를 묻는 화면이 US·UIUX 전수에 0건이고,
  되돌릴 수 없는 판정 필드를 확률적 쿼리 생성에 태울 수 없음(`V-09` 8번, 2차 후보로만 기록)
- 의미정보: **문서 코퍼스 RAG와 리랭킹 모델을 버림** — 색인할 문서가 없고, 리랭킹 1홉을 더하면
  `Q-1` 3,000ms 예산에서 LLM 호출(1,200ms) 다음의 가장 큰 지연이 됨
- 관계정보: **GraphRAG를 버림** — 그래프 적재·검수 구축 비용이 MVP 14주를 넘고, 부정 관계는
  정형 고정 쿼리로 더 안전하게 처리됨
- 용어사전: **사전 기반 자동 확장(미등록어 추론)을 버림** — 미등록어를 추론으로 채우면
  알레르겐 코드 매핑 실패가 조용히 통과할 수 있어 원문 유지 + 실패 표시로 둠

##### 의미정보(RAG)

뜻이 가까운 항목을 찾아옴. ④가 인덱스 이름까지만 정했으므로 나머지 7항목을 여기서 채움.

- **인덱스명** — `S-4 취향 벡터 인덱스`(④의 논리 이름을 그대로 씀). 물리 인덱스 이름은
  `preference_vector_index`이며 물리 배치는 ⑦ 배포가 정함
- **문서 범위·기준일** — 문서가 아니라 벡터 3종을 담음: ⓐ 회원별 취향 벡터(최신본 + 직전 1세대,
  ② ADR-5) ⓑ 음식 카드·메뉴 임베딩 ⓒ 선호 카테고리·반복 방지 패턴. 기준일은 **매일 03:00 배치
  갱신 시점**(③ `일일 취향 학습 배치 · S-B8` 커밋 시각)이고 온보딩 건은 이벤트 시점
  (③ `온보딩 완료 초기 프로파일 생성 · S-E6`). ⓑ의 원천이 확정되지 않음 →
  `[확인필요: 음식 카드 마스터 구축 주체·건수·태그 분류 체계]`
- **청킹 단위/크기/중첩** — 문서 청킹 **해당 없음**(문단으로 자를 텍스트가 없음). 색인 단위는
  회원 1명 = 취향 벡터 1건 · 음식 카드 1장 = 임베딩 1건이며 중첩 없음
- **임베딩 모델명·버전** — 생성 주체는 `TB-2` 모델 벤더이고 호출 단계는 ③ `S-B6`·`S-E5`임.
  모델 벤더의 임베딩 엔드포인트 규격을 확인하지 못함 →
  `[확인필요: 임베딩 모델명·버전·벡터 차원 수]`
- **검색방식 · top-k · 리랭킹 여부** — 코사인 유사도 검색 · **top-k 20** · **리랭킹 끔**.
  20은 추천 3개 + 거절 후 대체 1개 + 반복 방지(최근 3일 동일 식당 제외)와 하드 필터 통과 후보
  감소분을 덮는 값임(설계판단). 리랭킹은 위 버린 대안대로 `Q-1` 예산 때문에 끔
- **메타데이터 필터 키 이름·타입** — 아래 5건을 색인 시 **미리 선언**해 필터 목록에 올림

  | 필터 키 | 타입 | 무엇을 거르나 | 색인 시 값의 출처 | 질의 시 비교값의 출처 |
  |--------|------|-------------|----------------|-------------------|
  | `member_ref` | keyword | 본인 벡터만 보게 함(남의 취향 벡터 차단) | 커밋 대상 회원 참조 | ③ `K-6` `preference_vector_ref` · `K-46` `preference_vector_ref` |
  | `vector_generation` | integer | 최신본과 직전 1세대를 가름(되돌리기 대상 격리) | 커밋 세대 번호 | ③ `K-48` `quality_verdict`가 실어 주는 세대 판정 |
  | `item_type` | keyword | `preference_vector` · `food_card` · `menu` 를 섞지 않음 | 색인 항목 종류 | ③ `K-6` `route_mode`가 가리키는 경로 |
  | `category_code` | keyword | 카테고리(`KOR`·`WES`·`CHN`·`JPN`·`ETC`) 밖 항목 제외 | 음식 카드 마스터의 카테고리 | ③ `K-4` `context_snapshot`의 최근 7일 요약 |
  | `taste_tag` | keyword 배열 | 맛 태그(`SOUP`·`SPICY`·`NOODLE`) 밖 항목 제외 | 음식 카드 마스터의 맛 태그 | ③ `K-21` `keyword_label` |

  - 정하는 것은 **키 이름과 타입까지**임. 색인 시 값은 문서 원천이, 질의 시 비교값은 ③의
    전달 집합이 실어 줌
  - **선언하지 않은 키로 필터하면 오류 없이 결과 0건이 되어 권한 필터가 조용히 풀리는 제품이
    있음.** 쓰는 제품의 선언 방법을 확인해야 하나 `V-07` 3행이 제품을 특정하지 않음 →
    `[확인필요: 벡터 인덱스 제품 — 메타데이터 필터 키 사전 선언 방법]`. 제품 확정 전에는
    위 5개 키를 **선언 목록 문서**로 관리하고 색인 스키마에 그대로 옮김
  - **알레르겐·식이 유형·좌표·닉네임·직군은 필터 키로 세우지 않음** — 되돌릴 수 없는 판정과
    ② 경계 미통과 항목이므로 확률적 경로에서 아예 뺌
- **선택 근거 1줄** — 취향은 낱말 일치로 못 잡고(같은 한식이라도 국물·매운맛 선호가 갈림) 유사도
  검색만이 후보 정렬을 만들 수 있음

##### 관계정보(GraphRAG)

**미채택** — 아래 8항목 전부 `해당 없음`임.

- **노드 타입 목록** — 해당 없음
- **관계(엣지) 타입·방향** — 해당 없음(여기까지가 `그래프 스키마`이며, 이 항목을 `온톨로지`라고
  부르지 않음)
- **노드 고유키 규칙** — 해당 없음
- **추출·검수 방법** — 해당 없음
- **최대 홉 수 · 결과 상한** — 해당 없음
- **커뮤니티 요약 사용 여부** — 해당 없음
- **노드·관계 접근 필터**(경유 노드 검사 여부 포함) — 해당 없음
- **개념 계층·추론 규칙** — 해당 없음

부정 관계(`제외함`·`선택 안 함`)를 그래프에 세우지 않는 대신, 정형의 `diet_restriction` 표와
`excluded_ingredient_code` 열로 결정론 처리하고 하드 필터가 LLM 호출 **앞**에서 후보를 지움
(② ADR-3 · ③ `오늘의 추천 조회 · S-R8`). 갈래를 채택하지 않았으므로 접근 필터 칸도 비어 있음이
정상임.

### 1-3. 용어사전 — 덧붙는 층

경로가 아니며 위 경로 위에 얹음. 7항목을 전부 채움.

- **사전 파일 위치·형식** — 파일명 `food_taxonomy.csv`(UTF-8 CSV). 열 구성은
  `surface_form`(원문 낱말) · `canonical_term`(대표어) · `term_type`(`category`·`taste`·
  `feedback_keyword`) · `code`(`category_code`·`taste_tag`·`keyword_label` 중 하나) ·
  `priority`(정수, 1이 우선). 배포 경로는 ⑦ 배포가 정함
- **대표어·동의어 목록** — 대표어 3계열임

  | 계열 | 대표어 · 코드 | 근거 출처 |
  |------|-------------|----------|
  | 카테고리 | `한식`=`KOR` · `양식`=`WES` · `중식`=`CHN` · `일식`=`JPN` · `기타`=`ETC` | US:UIUX#인사이트(카테고리 Top 5 · 달력 색상 태그) |
  | 맛 태그 | `국물`=`SOUP` · `매운맛`=`SPICY` · `면`=`NOODLE` | US:UIUX#추천카드(컨텍스트 태그 표기) |
  | 피드백 키워드 | `맛`=`TASTE` · `양`=`PORTION` · `속도`=`SPEED` | US:UFR-REC-090#입력요구사항 |

  동의어(원문 낱말) 전량은 원문에 없음 → `[확인필요: 음식 카테고리·맛 태그 동의어 전량 목록]`
- **어디서 풀지** — 관계정보와 같은 셋에서 고름. 두 지점을 씀
  - **넣을 때 풀기**(적재 시점) — 벡터 색인 때 `category_code`·`taste_tag`를 대표어 코드로
    정규화해 함께 넣음
  - **물을 때 풀기**(질의 확장) — 정형 집계 쿼리와 벡터 필터에 넘길 낱말을 대표어 코드로 바꿔 찾음
  - **찾은 뒤 풀기**(조회 시점) — 쓰지 않음(찾은 뒤 사전으로 더 끌어오면 하드 필터가 지운 후보가
    되살아날 수 있음)
- **보여줄 때 고를 표기** — **대표어로 통일해 보임**. 달력 색상 태그·인사이트 Top 5·추천 카드
  컨텍스트 태그가 모두 대표어 기준이라 화면마다 낱말이 갈리면 안 됨(US:UIUX#인사이트)
- **어느 경로에 얹는지** — **정형**(집계 쿼리·집계 뷰의 카테고리 코드 정규화) +
  **의미정보**(색인 시 정규화 · 질의 시 필터 키 값 변환) 두 곳에 얹음.
  관계정보는 미채택이라 얹지 않음. 배타적 경로로 세지 않음
- **1:N 충돌 처리 규칙** — 한 낱말이 두 대표어에 걸리면 `priority` 최솟값을 씀. 값이 같아
  가려지지 않으면 매핑하지 않고 `category_code`를 `UNMAPPED`로 남기고 감사 로그
  (`tool_call_audit_log`)에 1행 남김. **후보를 지우지는 않음**.
  알레르겐 코드 매핑은 이 사전이 다루지 않음 — ③ `온보딩 완료 초기 프로파일 생성 · S-E2`의
  결정론 검사이며 실패 시 그 식재료를 전체 제외하는 페일세이프임(US:UFR-MBR-040#검증요구사항)
- **미등록어 처리 규칙** · **갱신 주체·주기** — 미등록어는 원문을 그대로 유지하고 `UNMAPPED`로
  표시하며 대표어로 바꾸지 않음. 갱신 주체·주기는 원문에 없음 →
  `[확인필요: 용어사전 갱신 주체·주기]`

## 2. 도구(커넥터)

④ 역할계약서의 `사용 도구`로 받은 외부 시스템에 커넥터 번호를 붙임. `TB-5` 외부 인증은 ④가
담당자 전원 `0건`으로 적었고 ③의 워크플로우 밖이므로 커넥터를 만들지 않음. `TB-2`는 문장 생성과

### 입출력 키

### 접근 제한 4종의 경계

이름이 비슷해 헷갈리므로 막는 층이 다름을 밝힘. 하나로 합쳐 적지 않음. 갈래마다 제 몫의 필터가
있고 그 위에 값을 가리는 층이 얹힘.

| 무엇 | 어디 | 막는 층 | 이 문서의 상태 |
|------|------|--------|--------------|
| `정형 접근 금지 컬럼` | 1-1 정형정보 | `표.열`을 **아예 조회 안 함** | 9행 기입(채택 갈래) |
| `메타데이터 필터 키` | 1-2 의미정보 | 비정형 항목 중 **못 볼 것을 걸러냄** | 5건 기입, 타입 전건 명시(채택 갈래) |
| `노드·관계 접근 필터` | 1-2 관계정보 | 따라갈 수 있는 **노드·관계를 제한함**(경유 노드 포함) | `해당 없음` — 갈래 미채택 |
| `변환 지점(TB-n)` | 3 민감·보존 | **조회는 되나 값을 가림** | `F-1` ~ `F-13` 13행 기입 |

채택한 갈래(정형 · 의미정보 · 용어사전) 가운데 필터 칸이 빈 갈래 **0건**임 —
용어사전은 경로가 아니라 얹는 층이므로 자체 필터를 갖지 않고 얹은 두 경로의 필터를 그대로 씀.
