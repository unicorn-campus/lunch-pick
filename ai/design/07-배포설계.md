# 설계서 ⑦ 배포 — 런치픽(LunchPick)

**작성**: 커넥니(도구 연동 엔지니어) · **작성일** 2026-08-12
**입력**: `_shared/프로젝트정보.md`(`V-08`·`V-09`·`V-11`) · `02-논리아키텍처.md` · `05-지식도구설계.md` ·
`03-워크플로우설계.md` · `04-역할계약서.md` · `06-가드레일관측설계.md` · 기획 산출물 `docs/plan/`
**미검증 설계** — 실제로 이미지를 굽고 클러스터에 올려 본 결과가 아니라 앞 산출물의 값과 요구 원문에서
도출한 배치임. 포트 응답·비밀값 주입·되돌리기 절차 중 어느 것도 실행으로 확인하지 않았음.

이 문서는 **"이 시스템을 몇 덩어리로 포장해 어디에 올리고 열쇠를 어떻게 넣는가"**에 답함.
`P-n`은 프로세스(② 소유) · `S-n`은 내부 저장소(② 소유) · `TB-n`은 Trust Boundary(신뢰 경계, ② 소유) ·
`C-n`은 커넥터(⑤ 소유) · `R-n`은 담당자(④ 소유) · `W-n`·`S-R`·`S-B`·`S-E`는 워크플로우·단계 식별자(③ 소유)임.
`D-n`은 이 문서가 붙인 배포 단위 번호임.

**이 문서가 소유하는 값** — 배포 단위 · 포트 · 비밀값 주입 경로 · 저장소 배치.
**이 문서가 소유하지 않는 값** — 프로세스 경계·저장소 목록(②) · 표·인덱스·커넥터 번호(⑤) ·
사용 모델(④) · 타임아웃·재시도(③) · 마스킹 방법·기록 항목(⑥).

## 판정 기록 1 — 나눌까 합칠까(가이드 2-1 4문)

기본은 1덩어리임. `Q1` ~ `Q3` 중 하나라도 `예`면 나눔 후보이고 `Q4`가 `아니오`면 무조건 합침.

| # | 질문 | 답 | 그 이유 |
|---|------|:--:|--------|
| 1 | 배포 형태가 다른가 | **예** | 프론트엔드는 정적 자원을 CDN 엣지에 올리는 `정적 호스팅`이고 나머지 4단위는 `런타임 이미지`임 |

| 3 | 접근 권한 등급이 다른가 | **예** | 회원은 건강·계정 정보와 별도 암호화 키를 만지고, 결제는 PG 가맹점 자격을 쥠. 축이 서로 다름 |
| 4 | 나눠도 응답시간 목표를 지키나 | **예** | ③이 프론트 → 추천업무 접수 20ms(`S-R2`)와 회원·이력 조회 홉을 3,000ms 예산 안에 이미 배정했고 총합이 예산을 넘지 않음 |

`Q4`가 `예`이므로 합치지 않음 — **5덩어리로 나눔.**

**줄이는 순서를 미리 적음** — 부담을 줄여야 할 때 무엇을 먼저 합칠지와 그 대가임.

## 3-1. 단위

### 런타임 규모 상한의 근거 계산

숫자를 지어내지 않고 US:NFR-SYS-020#체크리스트의 세 값에서 계산했음 — 동시 사용자 1,000명 ·
CPU 70% 이상 시 자동 확장 · **DB 커넥션 풀 최대 100개**.

```
인스턴스당 커넥션 풀      = 8   (설계판단)
피크 동시 최대 인스턴스   = D-1 3 + D-2 6 + D-3 2 = 11
피크 커넥션 소요          = 11 × 8 = 88
배치 구간 추가            = D-5 1 × 8 = 8
합계                      = 96 ≤ 100  → 커넥션 풀 상한을 넘지 않음
```

`D-5`의 최소가 0인 이유는 03:00 실행 창 밖에서는 인스턴스가 없어야 낮 피크와 자원을 다투지 않기
때문임(② ADR-2 · `P2`). `D-3`을 고정 2로 둔 이유는 ②가 결제업무의 `P2`(늘리는 축)를
`아니오`로 판정했고 배포 중 중단을 막을 최소치가 2이기 때문임.

### 분할 근거

`Q1 예 · Q2 예 · Q3 예 · Q4 예` → **나눔**(5덩어리).

- `Q1 예` — `D-4`만 정적 호스팅이고 나머지는 런타임 이미지임
- `Q2 예` — `D-2`는 피크 12 ~ 13시, `D-5`는 03:00, `D-1`·`D-3`은 평탄함
- `Q3 예` — `D-1`은 건강·계정 정보와 별도 암호화 키, `D-3`은 PG 가맹점 자격, `D-2`·`D-5`는
  모델 벤더 자격을 쥠
- `Q4 예` — ③이 프론트 → 추천업무 접수 `S-R2` 20ms와 회원·이력 조회 홉을 3,000ms 예산 안에 이미
  배정했고 합계가 예산을 넘지 않음. 거부권 문항이 `아니오`가 아니므로 합치지 않음

**알림 발송 배치(③ `W-8`)를 `D-2`에 둔 이유** — 담당자 `R-D3`가 `S-3`·`S-6`·`S-7`을 읽어 본문을

시간대라 늘리는 축이 `D-2`와 같음. ②의 프로세스 분리표에 이 배치의 소속이 없어 부속 표에
`변경요청` 1행을 남김 — `설계판단`(③ `W-8` · ② 판정 기록 6 `P2`).

**`D-5`를 별도 단위로 둔 근거** — ②가 프로세스 분리표에서 소속을 `[확인필요]`로 열어 두었으나
같은 문서의 ADR-2가 `ⓑ 별도 프로세스`로 결정했으므로 그 결정을 따라 별도 배포 단위로 확정함.

## 3-4. 되돌리기

### 단위별 되돌리기

값은 배포 단위 표의 `되돌리기` 열에 있음. 단위마다 1줄씩 채워졌고 공란 **0건**임.

| 단위 | 되돌리는 방법 | 못 돌아오는 부분 |
|------|-------------|---------------|
| `D-1` 회원 API | 직전 이미지 태그로 교체 | 스키마 변경을 함께 냈으면 코드만 돌아옴 — 아래 데이터 변경 표 6번을 봄 |
| `D-2` 추천·이력 API | 직전 이미지 태그로 교체 | 이미 나간 알림은 회수 불가 — 데이터 변경 표 3번 |
| `D-3` 결제 API | 직전 이미지 태그로 교체 | 이미 등록된 정기 결제는 회수 불가 — 데이터 변경 표 2번 |
| `D-4` 프론트엔드 | 직전 정적 빌드 판본으로 교체 + 엣지 캐시 무효화 | 캐시 무효화가 퍼지는 동안 이전 판본이 잠시 함께 보임 |
| `D-5` 일일 취향 학습 배치 | 직전 이미지 태그로 교체 + 이전 세대 벡터 유지 | 이미 커밋된 세대는 세대 열로 되돌림(데이터 변경 표 1번) |

### 되돌릴 수 없는 데이터 변경

**코드는 돌아가는데 데이터가 안 돌아오는 자리임.** ④가 `쓰기(되돌림 불가)`를 2건만 적었어도 이
표는 비지 않음 — ④는 외부 부작용을 보고 ⑦은 데이터 원복 수단을 봄. 축이 달라 둘 다 참임.

| # | 무엇이 되돌아오지 않나 | 직전 값 1세대 보관 여부 | 배포 전 준비 |
|---|---------------------|--------------------|------------|
| 1 | `D-5` 배치가 덮어쓴 취향 벡터(`S-4` 커밋 결과) | **보관함** — 최신본 + 직전 1세대(② ADR-5 · ⑤ 보존 표) | 세대 번호를 올려 커밋하고 이전 세대를 지우지 않음. 첫 판은 배치를 끈 채 올리고 세대 확인 뒤 켬 |
| 2 | `TB-6` 정기 결제 등록 결과(외부 PG에 남은 등록 상태 · `payment_id`) | **보관하지 않음** — 등록 전 상태로 되돌릴 수단이 없고 취소는 별도 청약철회 절차임 | `billing` 스키마는 추가만 먼저 배포하고 삭제·이름 변경은 다음 판으로 넘김 |
| 3 | `TB-7` 푸시·알림 발송 결과(단말로 이미 나간 알림 · 발송 기록) | **보관하지 않음** — 단말에 도착한 알림을 회수할 수 없음 | 중복 방지 키를 먼저 배포해 재실행 때 두 번 나가지 않게 함 |
| 4 | `S-2` 위치 좌표의 6개월 만료 삭제 결과 | **보관하지 않음** — 법정 파기이므로 직전 값을 남기는 것 자체가 위반임 | 삭제 판정 기준을 바꿀 때는 기준만 먼저 배포하고 실제 삭제 활성은 다음 판으로 넘김. 삭제 실행 기록만 `S-7`에 남김 |
| 5 | `S-3` 무료 30일 경계 도달 기록 삭제 결과 | **보관하지 않음** — 보존 판정에 따른 파기라 사본을 남기지 않음 | 유예 상태(결제 실패 7일)를 먼저 배포해 유예 중 삭제가 돌지 않게 함 |
| 6 | 정형 접근 금지 컬럼 정리로 지운 열(카드 원문 열 · 접근 로그 원문 값 열) | **보관하지 않음** — 애초에 만들지 않기로 한 열이라 사본을 두지 않음 | 추가만 먼저 배포하고 삭제는 다음 판으로 넘김(⑤ 정형 접근 금지 컬럼) |
| 7 | 용어사전 판본 교체로 바뀐 `UNMAPPED` 매핑 결과 | **보관함** — 직전 판본 파일 1세대를 설정 객체에 함께 둠 | 판본을 바꿀 때 이전 판본을 지우지 않고 참조만 바꿈 |

**7행 · `직전 값 1세대 보관 여부` 공란 0건**(필수 칸이라 판정을 다 적었음).
