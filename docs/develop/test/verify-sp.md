## 시각적 일관성

### 컬러 시스템 (8/10)
- **Primary (오렌지 #F97316 계열)**: 로고, CTA 버튼, 진행률 바, 달력 오늘 날짜, 매칭률 별, 확신 스코어 바 등 전 페이지에서 일관 적용
- **Secondary (카카오 노란색)**: 로그인 페이지 카카오 버튼에만 한정 사용 — 브랜드 충돌 없음
- **Success (초록 #10B981 계열)**: 식사 기록 체크 애니메이션, 피드백 완료 상태에서 일관 사용
- **배경**: 전체적으로 흰색(#FFFFFF) 베이스 + 카드형 컴포넌트에 연한 회색 테두리 — 깔끔한 인상
- **개선점**: 위치 동의 아이콘(민트 계열)이 오렌지 Primary와 약간 이질감. 프로필 페이지 섹션 아이콘 컬러가 다양(빨강, 노랑, 초록 등)하여 통일성 다소 저하

### 타이포그래피 (9/10)
- 페이지 제목(Bold, 큰 사이즈), 카드 제목(Semi-bold), 본문(Regular), 보조 텍스트(회색, 작은 사이즈)로 명확한 4단계 위계
- 추천 카드 내 AI 이유 텍스트가 이탤릭+따옴표로 구분 — 일반 정보와 AI 생성 콘텐츠의 시각적 차별화 적절
- 한글 가독성 우수, 줄간격 적절

### 아이콘 (8/10)
- 음식 이모지(퀴즈 카드), 기능 아이콘(위치, 알림, 구독), 액션 아이콘(좋아요/싫어요 이모지) 혼재
- 하단 네비게이션 바 아이콘은 4개 탭 모두 통일된 스타일
- **개선점**: 이모지와 커스텀 아이콘이 혼용되어 시각적 톤 불일치가 간헐적으로 발생 (퀴즈 카드 이모지 vs 프로필 설정 아이콘)

### 간격/레이아웃 (8/10)
- 카드 간 여백, 섹션 간 여백이 전 페이지에서 일관적 (약 16-24px 추정)
- 바텀시트 내부 패딩도 균일
- **개선점**: tc-04.png(퀴즈 결과) 페이지에서 트로피 아이콘 위 공백이 과도 — 세로 중앙 정렬이나 상단 콘텐츠 추가 권장

## 정보 계층 및 가독성

### 핵심 정보 즉시 인지 (9/10)
- **매칭률**: 별 아이콘 + 퍼센트 숫자가 카드 우측 상단에 고정 배치 — 3개 카드 스캔 시 즉시 비교 가능
- **도보 거리**: 핀 아이콘 + "도보 N분 | NNNm" 포맷으로 통일 — 의사결정에 핵심인 거리/시간 정보가 바로 보임
- **식당명/카테고리**: "광화문 된장마을 (한식)" — 이름과 카테고리를 한 줄에 배치하여 스캔 효율 극대화
- **AI 추천 이유**: 이탤릭 따옴표로 자연어 한 줄 — 카드 하단에 위치하여 "왜 이 식당인지"를 바로 파악

### CTA 명확성 (9/10)
- "여기 갈래요" (오렌지, 우측): 수락 행동의 시각적 무게감 적절
- "왜?" / "거절" (텍스트 링크, 좌측): 보조 액션으로 무게감 낮춤
- "먹었어요!" (큰 원형 오렌지 버튼): 원탭 기록의 시각적 어포던스 명확
- "취향 분석 완료!" (풀 가로 오렌지 버튼): 퀴즈 완료 시 달성감과 함께 다음 단계 유도
- **"실행 취소" 카운트다운 바**: 하단 다크 배경 + 남은 초 표시 — 긴급성과 안전망 동시 전달

### 개선 필요 항목
- tc-15.png: "기록 중 오류가 발생했어요" — 409 중복 기록인 경우 "이미 오늘 기록이 있어요"로 구체화 필요

- tc-insights.png: 빈 상태 화면이 텍스트만으로 구성 — 진행 게이지나 일러스트 추가 시 동기부여 강화 가능

## MINOR 이슈 검토 (e2etest-5.md 기준)

### MINOR-01: 409 중복 기록 시 일반 에러 메시지
- **SP 판단**: P1 개선 필수
- **근거**: 식사 기록은 서비스 핵심 루프의 마지막 단계. "기록 중 오류"라는 모호한 메시지는 사용자를 불안하게 만든다. "이미 오늘 기록이 있어요. 이력에서 수정할 수 있어요." 등 구체적 안내와 다음 액션 제시가 필요하다.

### MINOR-02: 결제 실패 시 API 응답 메시지 미반영
- **SP 판단**: P1 개선 필수
- **근거**: 결제 실패 상황에서 사용자가 "왜 실패했는지", "무엇을 해야 하는지" 모르면 이탈 확률이 높다. 특히 결제 페이지에서의 이탈은 직접적인 매출 손실이다. API가 이미 "다른 결제 수단을 시도해주세요" 메시지를 반환하므로 이를 표시만 하면 된다.

### MINOR-03: payment-service / member-service 상태 불일치
- **SP 판단**: P1 개선 필수 (서비스 신뢰도 직결)
- **근거**: 결제 완료 후 프리미엄이 즉시 활성화되지 않으면 사용자는 "돈만 빠져나간 것 아닌가"라는 불안을 느낀다. 비동기 이벤트 전파의 최종 일관성(eventual consistency)이라 해도, UI에서는 결제 직후 낙관적 업데이트(optimistic update)로 즉시 프리미엄 상태를 표시하고, 백그라운드에서 동기화하는 패턴이 필요하다.

## 결론

런치픽 MVP는 서비스 기획 관점에서 **핵심 유저 여정의 완성도가 높다**. 특히 다음 세 가지가 인상적이다.

1. **추천 카드의 정보 설계**: 식당명, 카테고리, 대표메뉴, 매칭률, 거리, AI 이유를 한 카드에 담으면서도 시각적 혼잡함이 없다. 사용자가 3개 카드를 스캔하고 의사결정하는 데 필요한 모든 정보가 즉시 인지 가능하다.

2. **식사 기록 + 피드백 + 실행 취소의 한 화면 통합**: 기록 완료 후 바로 피드백을 유도하면서, 30초 실행 취소 안전망까지 제공하는 설계가 사용자 심리를 잘 반영했다. "실수해도 돌릴 수 있다"는 안전감과 "한 번 더 알려주면 내일 더 잘 추천해준다"는 동기부여가 공존한다.

3. **온보딩 이탈 방지 설계**: 모든 단계에 "건너뛰기"를 두면서도, 진행률 바와 격려 메시지로 완주를 유도하는 당근+채찍 구조가 효과적이다.

P1 개선사항 3건(에러 메시지 구체화 2건 + 구독 상태 동기화 1건)을 해결하면 **PASS**로 전환 가능하다.
