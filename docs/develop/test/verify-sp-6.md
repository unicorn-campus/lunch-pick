## UI/UX 검증

### 전체 디자인 시스템

#### 색상 체계
- Primary Color (#FF6B35, 오렌지): 버튼, 확신 스코어, 진행률 바, CTA 등에 일관되게 적용됨. 스타일 가이드 준수.
- Success 색상 (#10B981, 민트 그린): 위치 동의 완료 토스트에 적용됨. 감정적으로 긍정적인 메시지 전달 성공.
- Error 색상 (#EF4444, 레드): 로그인 실패 토스트, 기록 오류 토스트에 적용됨. 상태 컬러 체계 일관성 유지.
- Info 색상 (#3B82F6): 위치 비활성화 토스트(파란색 배경)에 적용됨. 그러나 "위치 기반 추천이 비활성화되었어요"는 경고성 메시지임에도 Info 색상이 사용되어 감정 일치성이 다소 낮음(Minor).

#### 타이포그래피
- Pretendard 계열 폰트가 전반적으로 적용됨. 한글 가독성 양호.
- 추천 카드의 추천 이유 텍스트가 이탤릭체(기울임꼴)로 표시되어 시각적 차별화가 명확함. 기획서 "추천 이유 한 줄" 요건 충족.
- 캡션급 텍스트(도보 거리, 시간)는 충분히 가독성 있는 크기로 표시됨.

#### 컴포넌트 일관성
- 추천 카드: 식당명, 카테고리, 확신 스코어(%), 대표 메뉴, 도보 시간, 추천 이유 한 줄, [왜?] [거절] [여기 갈래요] 버튼 구성이 3개 카드 모두 동일하게 유지됨. 일관성 우수.
- 바텀시트: 추천 이유 상세(tc-10), 거절 사유(tc-12), 해지 확인(tc-24) 모두 동일한 바텀시트 패턴 사용. 드래그 핸들은 tc-10, tc-12에서 확인됨.
- 토스트/스낵바: 성공(민트), 오류(레드), 정보(파란) 색상 구분이 명확함.
- 하단 탭바 4탭(홈/이력/인사이트/프로필) 구조가 모든 주요 페이지에서 일관되게 표시됨.

- 사용자 입장에서 에러 메시지가 중복으로 보이면 혼란을 줄 수 있음.
- **[Major-01]** 에러 토스트 중복 표시.

#### 위치 동의 / 식이제한 (tc-05, tc-05-dietary, tc-06)

**tc-05 / tc-05-dietary — 위치 동의 후 식이제한 페이지**
- 위치 허용 시 "위치 기반 추천이 활성화되었어요." 토스트(민트 초록)가 하단에 표시되며 식이제한 설정 페이지로 이동함.
- 식이제한 페이지: 알레르기 항목 칩(난류, 우유, 메밀, 땅콩, 대두, 밀, 고등어, 게, 새우, 돼지고기, 복숭아, 토마토, 아황산류, 호두, 닭고기, 쇠고기, 오징어, 조개류), 직접 입력 필드, 식이 유형(일반/채식/비건/할랄/기타), 건강 관련 정보 수집 동의 체크박스가 모두 표시됨.
- "일반" 식이 유형이 Primary Color(오렌지)로 선택된 상태로 기본값이 시각적으로 명확함.
- **[Minor-02]** 식이제한 설정 페이지 하단에 "설정 완료" CTA 버튼이 스크린샷 뷰포트 밖에 위치하여 보이지 않음. 사용자가 스크롤이 필요하다는 것을 인지하지 못할 수 있음. 건강 동의 체크박스 아래 CTA 버튼의 가시성 확보 필요.

**tc-06 — 위치 거절**
- "위치 기반 추천이 비활성화되었어요." 토스트(파란 배경, Info 색상)가 하단에 표시됨.
- 기능적으로 정상 동작하나, 위치 비활성화는 서비스 품질 저하를 의미하는 메시지임에도 Info(파란색)보다는 Warning(노란색)이 더 적합한 감정 상태를 전달할 수 있음.
- **[Minor-03]** 위치 비활성화 토스트 색상이 Warning이 아닌 Info 색상 적용.

#### 홈 — AI 추천 카드 (tc-07, tc-08, tc-09, gap-03, gap-08-demo)

**tc-07 / tc-08 / tc-09 — 홈 추천 카드 3개**
- 상단 헤더: "현재 위치" (핀 아이콘), "런치픽" 로고 중앙, 알림 아이콘(우측). 기획서 레이아웃과 일치.
- 인사말: "안녕하세요, 런치픽님!" — 닉네임 자리에 "런치픽"이 표시됨. 테스트 계정의 닉네임이 "런치픽"으로 설정되어 있어 가능하나, 실제 사용자 닉네임이 서비스 브랜드명과 동일하게 표시되면 의도치 않은 혼란을 줄 수 있음. 모니터링 필요(Minor).
- "어제 피드백 반영" 태그가 상단에 표시됨. 기획서의 학습 반영 가시화 요건 충족.
- 추천 카드 3개: 1. 광화문 된장마을(한식) 87% / 2. 사쿠라 스시(일식) 86% / 3. 이탈리아 파스타(양식) 85%.
- 각 카드에 식당명, 카테고리, 확신 스코어, 대표 메뉴, 도보 거리, 추천 이유 한 줄(이탤릭), [왜?] [거절] [여기 갈래요] 버튼 구성. 기획서 와이어프레임과 일치.
- 하단 탭바가 카드 중간에 겹쳐 보임. 2번째 카드 하단과 3번째 카드 상단 사이에 탭바가 오버레이됨.
- **[Major-02]** 하단 탭바가 3번째 추천 카드를 부분적으로 가림. 3번째 카드의 식당명("이탈리아 파스타") 영역이 탭바와 겹쳐 렌더링됨. 사용자가 3번째 추천을 확인하려면 스크롤이 필요한데, 탭바 뒤에 콘텐츠가 있다는 시각적 신호가 불분명함.

#### 추천 이유 바텀시트 (tc-10)

**tc-10 — "왜?" 바텀시트**
- "광화문 된장마을을 추천한 이유" 제목, 자연어 설명("된장찌개 정식은(는) 주변 직장인들에게 인기 있는 메뉴예요. 취향 데이터 기반으로 추천드려요."), 확신 스코어(87% 프로그레스 바), 반영된 컨텍스트("취향" 태그), [여기 갈래요] CTA 버튼이 표시됨.
- 기획서 바텀시트 설계와 대체로 일치.
- **[Minor-04]** 반영된 컨텍스트 태그가 "취향" 1개만 표시됨. 기획서에서는 날씨, 이력, 취향 등 복수의 컨텍스트 태그가 표시되어야 하며, "어제 피드백 반영 ✓" 태그도 포함되어야 함. 현재 구현은 태그가 최소화되어 추천 투명성 전달이 약함.
- **[Minor-05]** 바텀시트에 드래그 핸들이 존재하나 닫기(X) 버튼 또는 오버레이 탭으로 닫기 방법이 명시적으로 보이지 않음. 접근성 측면에서 닫기 버튼 명시 권장.

- **[Major-03]** 식사 기록 화면에서 [먹었어요!] 버튼 탭 후 피드백 UI(좋아요/별로, 키워드 칩)가 스크린샷에 나타나지 않음. tc-18(피드백 제출), tc-19(피드백 건너뛰기) 모두 동일하게 [먹었어요!] 버튼만 보이는 상태로 캡처됨. 기획서(UFR-REC-090)에서 핵심 기능인 "좋아요/별로 + 키워드" 피드백 UI가 화면에 표시되지 않는 상태로 스크린샷이 캡처된 것으로 보임. E2E 테스트는 요소 존재 여부만 확인하여 PASS 처리되었으나, 실제 사용자 경험 상 피드백 UI 접근이 불명확함.

**tc-16 / tc-17 — 실행 취소 바**
- tc-16(20초 이내): 하단 탭바 위에 실행 취소 바가 표시되어야 하나, 스크린샷에서는 [먹었어요!] 버튼만 표시되고 실행 취소 바가 보이지 않음.
- tc-17(30초 초과): 동일하게 [먹었어요!] 버튼만 표시됨. 실행 취소 바 미표시로 tc-16과 시각적 차이가 없음.
- **[Major-04]** 실행 취소 바(Undo Bar)가 스크린샷에서 확인되지 않음. 기획서(UFR-REC-080)에서 "30초 카운트다운 타이머 + 실행 취소 버튼" UI가 핵심 요소이며, E2E 테스트는 "취소 바 또는 되돌리기 UI 확인"으로 PASS 처리됨. 그러나 스크린샷에는 해당 UI가 없어 실제 렌더링 여부가 불명확함.

## 종합 의견

### 잘된 점 (Keep)

1. **핵심 루프 완성도**: 로그인 → 온보딩(퀴즈/위치/식이) → 홈(추천 3개) → 이유 확인(바텀시트) → 수락(길찾기) → 거절(사유 바텀시트) → 구독 관리까지 핵심 플로우가 중단 없이 작동함. 기획 의도인 "결정 피로 해소" 플로우가 구현됨.

2. **추천 이유 투명성**: 확신 스코어(%), 자연어 추천 이유, 컨텍스트 태그를 통해 "광고가 아닌 내 취향 기반" 신뢰를 시각적으로 전달하는 요소들이 구현됨. "어제 피드백 반영" 태그가 홈 화면에 표시되어 학습 반영 가시화 원칙 충족.

3. **피드백 UI 및 에러 처리**: 에러 토스트(API 500/409/402 에러 시)가 일관된 색상과 메시지로 표시됨. Graceful Degradation이 실제 동작함. 크래시 없음.

4. **모바일 최적화**: 375px 뷰포트(gap-04-mobile)에서 레이아웃 깨짐 없음. 카드, 버튼, 탭바 모두 정상 렌더링. Mobile First 원칙 준수.

5. **구독 법적 고지**: 청약철회권 7일, 자동 갱신, 무료 체험 기간 안내가 구독 페이지에 명시되어 전자상거래법 준수 요건 충족.

6. **Fallback UI**: 카카오맵 SDK 실패 시 "지도를 불러올 수 없습니다 + 외부 지도 앱 연동" 폴백이 자연스럽게 작동함. 길찾기 기능이 SDK 의존 없이 동작함.

### 개선 필요 사항 (Change)

1. **식사 기록 페이지 UX 완성**: [먹었어요!] 탭 후 피드백 UI 표시와 실행 취소 바가 스크린샷에서 확인되지 않음. 원탭 기록 후 이어지는 UX 흐름(피드백 → 실행 취소)이 사용자에게 명확하게 전달되어야 함. 가장 핵심적인 데이터 수집 루프이므로 우선 점검 필요.

2. **홈 탭바 가림 현상**: 3번째 추천 카드가 하단 탭바에 가려지는 레이아웃 이슈. 사용자가 3번째 추천을 자연스럽게 확인하려면 스크롤 공간 확보가 필수. padding-bottom으로 해결 가능한 간단한 수정임.

3. **구독 플랜 비교 레이아웃**: 무료 vs 프리미엄 병렬 비교 구조가 기획서와 달리 구현됨. 구독 전환 결정을 돕는 핵심 화면이므로 기획서 설계 방향으로 개선 필요.

4. **로그인 에러 토스트 중복**: 동일 에러 메시지 2개 표시는 신뢰감을 낮춤. 간단한 상태 관리 수정으로 해결 가능.

### 사용자 여정 관점 평가

유저 저니 맵의 핵심 Pain Point인 "탐색 13~18분" 문제를 해결하는 "즉각 추천 3개" 화면은 구현됨. 그러나 또 다른 핵심인 "피드백 루프 형성"(5단계)의 UI 완성도가 스크린샷 기준으로 확인이 어려워, 취향 학습 선순환의 핵심 UX가 사용자에게 제대로 전달되고 있는지 추가 검증이 필요함.
