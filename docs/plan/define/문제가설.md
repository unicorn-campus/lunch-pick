## 핵심 문제 선정

### 문제 1: 탐색이 결정으로 이어지지 않는다

**현상**: [PIVOT] 직장인은 점심 메뉴를 고르기 위해 평균 13~18분을 탐색하지만, 탐색 후에도 결국 기존에 검증된 단골 식당으로 회귀한다. 탐색에 투자한 시간과 에너지가 결정 품질을 높이지 못한다. 핵심 메커니즘은 "선택지 과부하"가 아니라 **"기억 없는 탐색의 반복"**이다: 어제 먹은 것을 기억하지 못한 채 탐색을 시작하면 같은 선택지가 반복되고, 반복된 선택지는 결정 피로를 누적시키며, 결국 익숙한 단골로 회귀한다. 이 구조는 문제 3(피드백 루프 단절)과 직접 연결된 단일 순환 고리를 형성한다.

#### 검증 결과

| 항목 | 수치 |
|------|------|
| 중요도 평균 (전체 15명) | **3.80 / 5.0** |
| 불편도 평균 (전체 15명) | **3.47 / 5.0** |
| 중요도 평균 (핵심 타깃 8명) | **4.50 / 5.0** |
| 불편도 평균 (핵심 타깃 8명) | **4.38 / 5.0** |
| 전체 근본원인 동의율 | **73%** (강하게 동의 33% + 부분 동의 40%) |
| 핵심 타깃 동의율 | **88%** |

**핵심 인터뷰 인용**:
> "매일 카카오맵 켜고 검색하는데, 결국 작년이랑 똑같은 데 가고 있어요. 시간만 쓰는 거죠." — 민준혁 (핀테크 개발자, 31세)

> "탐색 자체를 안 하게 됐어요. 6년 다니면서 쌓인 맛집 정보가 팀 바뀌고 나서 다 사라졌거든요." — 오채연 (금융 마케터, 38세)

**주석**: 부정 반응 4명 중 3명은 문제를 경험하지 않는 게 아니라 탐색 자체를 이미 포기(황소연, 황미영)했거나, 앱을 사용하지 않는 경우(임철수, 윤재호). 이는 문제 1의 심각한 결과 상태(탐색 포기)이지 문제 부재의 증거가 아님.

#### 5WHY 분석

| 단계 | 질문 및 응답 |
|:----:|-------------|
| WHY1 | 왜 사용자는 탐색 후에도 결정을 내리지 못하는가? → 어제 먹은 것, 최근 방문 이력이 탐색 도구에 기억되지 않아 매번 동일한 40~127개 선택지에서 출발하기 때문이다. 기억 없는 탐색은 필연적으로 반복과 결정 피로를 낳는다 |
| WHY2 | 왜 탐색 도구는 이전 식사 이력을 반영하지 않는가? → 현존 플랫폼(카카오맵, 네이버지도)은 지도 탐색 도구로 설계되었고, 개인 식사 이력을 추적·반영하는 메모리 기능이 설계 목표에 포함되지 않았기 때문이다 |
| WHY3 | 왜 지도 탐색 도구가 점심 결정의 주요 수단이 되었는가? → 식당 위치 정보를 한 번에 볼 수 있는 도구가 지도앱 외에 없었고, 전용 점심 결정 서비스가 시장에 부재하기 때문이다 |
| WHY4 | 왜 전용 점심 결정 서비스가 시장에 부재한가? → 점심 결정이라는 일상적 반복 행위를 독립 서비스로 수익화하는 모델이 검증되지 않았고, 플랫폼들이 광고 기반 수익모델에 최적화되어 있기 때문이다 |
| WHY5 | 왜 광고 기반 수익모델은 탐색-결정 단절을 구조적으로 고착시키는가? → 광고 수익은 더 많은 탐색 노출에서 발생하므로, 플랫폼이 사용자의 빠른 결정보다 긴 탐색 체류를 유도하는 방향으로 최적화되기 때문이다 |

#### 다층적 근본원인 검토

| 측면 | 근본 원인 | 중요도 |
|------|----------|:------:|
| 제도/시스템적 | 플랫폼 수익모델(광고)과 사용자 가치(빠른 결정)의 구조적 이해충돌. 탐색 체류 시간 극대화가 플랫폼 목표이므로 결정 지원 기능 개발 동기 부재 | ★★★★★ |
| 사용자 심리적 | [PIVOT] 단순한 선택 과부하(Choice Overload)를 넘어 "기억 없는 반복 탐색"이 핵심 메커니즘. 어제 먹은 것을 모르는 채 시작하는 탐색은 구조적으로 결정 실패를 내포한다 | ★★★★☆ |
| 맥락적 | 탐색 도구(지도앱)와 결정 맥락(어제 메뉴, 남은 시간, 현재 위치)이 통합되지 않은 분리 구조. 사용자가 수동으로 맥락을 처리해야 함 | ★★★☆☆ |
| 커뮤니케이션 | 추천 이유가 제공되지 않아 선택지 간 우열 판단 기준이 없음. "왜 이것을 골라야 하는가"에 대한 답이 탐색 결과에 없음 | ★★★☆☆ |

**핵심 근본원인**: [PIVOT] 플랫폼의 메모리 부재(식사 이력 미기록) + 광고 수익 구조의 결합이 "기억 없는 반복 탐색 → 결정 피로 → 단골 회귀"의 사이클을 매일 재생산한다. 이는 문제 3(피드백 루프 단절)과 동일한 순환 고리의 다른 진입점이다.

### 문제 2: 광고 기반 정보 왜곡으로 추천을 신뢰할 수 없다

**현상**: [PIVOT] 사용자는 지도앱·리뷰 플랫폼의 추천과 검색 결과가 광고·마케팅·오래된 정보로 오염되어 있다고 인식한다. 그러나 사용자들이 체감하는 핵심 문제는 "광고 수익 구조"라는 구조적 원인이 아니라, **"나를 위한 추천인지 알 수 없다"**는 신뢰의 공백이다. 광고 여부와 무관하게 "이게 왜 내게 추천되는지 모르겠다"는 불투명성이 신뢰 붕괴의 실질적 메커니즘이다. 플랫폼이 제공하는 정보를 신뢰하지 못해 "아는 사람 추천"에만 의존하게 되고, 그마저도 없을 때는 탐색을 포기하고 기존 단골로 회귀한다.

#### 검증 결과

| 항목 | 수치 |
|------|------|
| 중요도 평균 (전체 15명) | **3.73 / 5.0** |
| 불편도 평균 (전체 15명) | **3.53 / 5.0** — 세 문제 중 불편도 최고 |
| 중요도 평균 (핵심 타깃 8명) | **4.13 / 5.0** |
| 불편도 평균 (핵심 타깃 8명) | **4.25 / 5.0** |
| 전체 근본원인 동의율 | **80%** — 세 문제 중 최고 |
| 핵심 타깃 동의율 | **88%** |

**핵심 인터뷰 인용**:
> "광고인지 아닌지 모르겠는 게 더 무섭죠. 차라리 광고라고 표시해주면 걸러쓸텐데." — 손지훈 (스타트업 UX 디자이너, 28세)

> "광고 구조보다 정보가 오래됐다는 게 더 큰 문제예요. 지난달에 폐업한 식당이 아직도 1위로 뜨니까요." — 황소연 (HR 팀장, 42세)

**주석**: 근본원인("플랫폼 광고 수익 구조")에 강하게 동의한 비율은 27%(4명)에 그쳤다. 황소연은 "음모론처럼 들린다"고 언급. 이는 현상 진단은 옳지만 원인 프레이밍이 사용자 언어와 괴리됨을 의미한다. 커뮤니케이션 전략 수정 필요.

#### 5WHY 분석

| 단계 | 질문 및 응답 |
|:----:|-------------|
| WHY1 | 왜 사용자는 플랫폼 추천을 신뢰하지 못하는가? → 광고·협찬 식당이 상위에 노출되고, 마케팅 블로그 리뷰가 실제 고객 리뷰와 혼재되어 구분이 불가능하기 때문이다 |
| WHY2 | 왜 광고와 실제 추천이 구분되지 않는가? → 플랫폼이 광고 수익을 위해 유료 노출과 자연 검색 결과를 의도적으로 유사하게 설계하기 때문이다 |
| WHY3 | 왜 플랫폼은 광고와 자연 결과를 명확히 구분하지 않는가? → 구분이 명확해지면 광고 효과가 감소하고 수익이 하락하므로, 광고 수익 의존도가 높은 플랫폼에게 구분 명확화는 비즈니스 이해에 반하기 때문이다 |
| WHY4 | 왜 식당 정보 플랫폼이 광고 수익에 의존하게 되었는가? → 식당 정보 서비스를 사용자에게 무료로 제공하면서 수익을 창출할 수 있는 검증된 모델이 광고밖에 없었기 때문이다. 사용자 가치(신뢰 추천)를 수익화하는 모델이 미검증 상태였다 |
| WHY5 | 왜 신뢰 기반 추천의 수익화 모델이 검증되지 않았는가? → 개인화 추천 품질을 사용자가 직접 지불할 의향(Willingness to Pay)이 있다는 것이 시장에서 입증된 사례가 없어 플레이어들이 진입을 꺼렸기 때문이다 |

#### 다층적 근본원인 검토

| 측면 | 근본 원인 | 중요도 |
|------|----------|:------:|
| 사용자 심리적 | 반복된 광고 노출로 인한 플랫폼 불신 학습(Learned Distrust). 한 번이라도 광고 식당에서 실망하면 플랫폼 전체에 대한 신뢰를 철회하는 확증 편향 강화 | ★★★★★ |
| 제도/시스템적 | 과점 플랫폼(카카오맵, 네이버지도, 배달의민족)의 광고 기반 수익모델 구조. 독립 신뢰 채널이 시장에 부재하여 사용자가 대안 없이 기존 플랫폼을 계속 사용 | ★★★★★ |
| 커뮤니케이션 | [PIVOT] 추천 알고리즘의 불투명성이 핵심. "왜 이 식당이 내게 추천되는가"에 대한 설명이 없어 사용자는 광고 여부와 무관하게 의심을 기본값으로 작동시킨다. 7명이 추천 이유 설명을 직접 요청 | ★★★★☆ |
| 맥락적 | 리뷰 시점과 현재 상태의 괴리. 오래된 리뷰가 현재 식당 품질을 대표하지 않지만, 시간 정보가 검색 결과에서 부각되지 않아 사용자가 신구 정보를 구분하기 어려움 | ★★★☆☆ |

**핵심 근본원인**: [PIVOT] "나를 위한 추천인지 알 수 없다"는 설명 부재의 문제. 광고 여부를 떠나 추천의 근거(Explainability)가 없으면 사용자는 신뢰를 보내지 않는다. 과점 플랫폼의 광고 기반 구조는 이 문제의 배경 조건이지, 사용자가 직접 체감하는 핵심 Pain의 언어가 아니다.

### 문제 3: 식사 경험이 다음 선택에 반영되지 않는다

**현상**: [PIVOT] 사용자는 식사를 마친 후 만족도나 경험을 기록하지 않는다. 그 결과 오늘의 식사 경험이 내일의 더 나은 선택으로 연결되지 않고, 매일 동일한 탐색 고민이 반복된다. 이 문제의 핵심은 단순한 "피드백 미제공"이 아니라 **두 가지 기억의 부재**다: (1) 과거 식사 취향의 누적 기억 부재, (2) 오늘의 컨텍스트(몸 상태, 날씨, 시간 여유)를 반영하지 못하는 실시간 인식 부재. 두 기억의 부재가 결합될 때 "사용할수록 나아지지 않는 서비스"가 만들어진다.

| 중요도 평균 (핵심 타깃 8명) | **4.38 / 5.0** |
| 불편도 평균 (핵심 타깃 8명) | **4.00 / 5.0** |
| 전체 근본원인 동의율 | **73%** (강하게 동의 47% — 세 문제 중 최고) |
| 핵심 타깃 동의율 | **88%** |

**핵심 인터뷰 인용**:
> "별점 남겨봤자 내 추천이 달라진 적이 없어요. 그냥 남들한테 주는 리뷰잖아요, 나한테 돌아오는 게 없는." — 정수아 (스타트업 마케터, 31세)

> "어제 닭볶음탕 먹었으면 오늘은 국물 빠진 거 추천해줬으면 하는데, 그런 기능은 어디도 없더라고요." — 박성민 (콘텐츠 마케터, 34세)

**주석**: 강하게 동의 47%는 세 문제 중 최고. 단, 임도현(15번)이 "취향 학습보다 오늘 컨텍스트 반영이 더 중요하다"고 지적한 점이 핵심 피봇 근거. 취향 누적(장기 메모리)과 실시간 컨텍스트(단기 입력)는 대립이 아닌 보완 관계.

#### 5WHY 분석

| 단계 | 질문 및 응답 |
|:----:|-------------|
| WHY1 | 왜 사용자는 식사 후 평가를 남기지 않는가? → 평가를 남겨도 다음 추천이 달라지지 않는다는 것을 경험적으로 학습했고, 개인적 보상(시간 절약, 더 나은 추천)이 없기 때문이다 |
| WHY2 | 왜 기존 플랫폼은 개인 피드백을 다음 추천에 반영하지 않는가? → 현존 서비스들은 광고 노출 최적화를 위한 통계 기반 추천을 사용하며, 개인별 취향 학습(Personalization Loop) 엔진을 구현하지 않았기 때문이다 |
| WHY3 | 왜 플랫폼들은 개인화 학습 루프를 구현하지 않았는가? → 개인화 루프를 구축하려면 지속적인 피드백 수집 UX와 ML 파이프라인이 필요한데, 광고 수익 모델에서 이 투자의 ROI가 검증되지 않았기 때문이다 |
| WHY4 | 왜 피드백의 개인적 보상이 설계되지 않았는가? → 플랫폼 입장에서 리뷰는 다른 사용자를 위한 공공재로 설계되었고, 리뷰를 남긴 개인에게 즉각적으로 돌아오는 가치(내 추천 개선)가 설계 목표에 포함되지 않았기 때문이다 |
| WHY5 | 왜 플랫폼은 사용자 개인의 장기 가치보다 집단 데이터 가치를 우선했는가? → 광고 수익 모델은 집단 트래픽 데이터가 수익으로 직결되는 반면, 개인화 개선으로 인한 사용자 유지는 간접 수익이므로 우선순위에서 밀렸기 때문이다 |

#### 다층적 근본원인 검토

| 측면 | 근본 원인 | 중요도 |
|------|----------|:------:|
| 사용자 심리적 | 피드백의 개인적 보상 부재. "별점 주는 게 나에게 무슨 의미인가"라는 인식이 고착. 피드백을 남겨도 내 추천이 나아진다는 체감이 없어 행동 동기 소멸 | ★★★★★ |
| 제도/시스템적 | 광고 수익 최적화를 위한 집단 통계 추천 구조. 개인 피드백 루프 구현의 ROI 미검증으로 플랫폼의 기술 투자 동기 부재 | ★★★★☆ |

| 맥락적 | [PIVOT] 피드백 수집 타이밍의 미스매치 + 실시간 컨텍스트 반영 부재. 식사 직후 초간단 피드백(7명 요청)과 오늘의 컨텍스트 입력(날씨, 컨디션, 예산)을 결합해야 한다 | ★★★☆☆ |

## 문제 간 인과관계

3개 문제는 독립적이지 않다. 선형적 인과사슬과 악순환 루프를 형성한다.

```
[문제 2: 정보 신뢰도 훼손]
  "나를 위한 추천인지 알 수 없다" — 설명 부재 + 광고 혼재
  → 사용자가 플랫폼 추천을 불신, "아는 사람 추천"에만 의존
          ↓ (선행 원인)
[문제 1: 탐색-결정 단절]
  기억 없는 탐색의 반복 — 어제 먹은 것 모름 → 동일 선택지 반복 → 결정 피로 → 단골 회귀
  ↕ (단일 순환 구조 — 문제 1과 3은 하나의 악순환)
[문제 3: 피드백 루프 단절]
  기록된 취향 없음 + 실시간 컨텍스트 무시 → 추천이 나아지지 않음 → 피드백 동기 소멸
          ↓ (악순환 완성)
[문제 2로 복귀]
  개선 없는 추천 → "광고가 아닌가" 의심 강화 → 신뢰 공백 지속
```

**인과관계 해석 (피봇 후 업데이트):**
- 문제 2(정보 신뢰도 훼손)는 문제 1(탐색-결정 단절)의 구조적 선행 원인이다. 그러나 해결 방향은 "광고 배제 선언"이 아니라 "설명 가능한 개인화 추천(Explainable AI)"이다.
- 문제 1(탐색-결정 단절)과 문제 3(피드백 루프 단절)은 **분리된 독립 문제가 아니라 단일 순환 구조의 두 진입점**이다: "기억 없는 탐색 → 반복 탐색 → 결정 실패 → 피드백 포기 → 기억 없는 탐색". 솔루션은 두 문제를 동시에 타격해야 한다.
- 문제 3(피드백 루프 단절)의 해결은 단선형 취향 학습이 아닌 "기록된 취향(장기 메모리) + 오늘의 컨텍스트(단기 입력)"의 이중 인풋 구조가 필요하다.
- **단 하나의 통합 솔루션**: 3~5개로 압축된 설명 있는 추천 (Explainable AI) + 초간단 피드백 루프 (이모지·3택) + 식사 이력 자동 기록이 3개 문제를 동시 해소할 수 있는 최소 핵심 설계다.
