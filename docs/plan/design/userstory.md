## 1. 회원 서비스 (MBR)

### 1) 회원가입 및 온보딩

```
UFR-MBR-010: [소셜 로그인 회원가입] 사용자로서 | 나는, 빠르게 서비스를 시작하기 위해 | 카카오 계정으로 간편하게 회원가입하고 싶다.
Pain Point: 여정맵 1단계 — "또 뭐 먹지"라는 막막함, 빠른 시작 필요

- 시나리오: 정상적인 소셜 로그인 회원가입
  미로그인 상태에서 앱을 처음 실행한 상황에서 | 카카오 로그인 버튼을 탭하고 카카오 인증을 완료하면 | 회원가입이 완료되고 취향 온보딩 화면으로 이동한다.

  [입력 요구사항]
  - 카카오 인증 토큰

  [검증 요구사항]
  - 이메일 중복 확인: 기존 회원이면 로그인 처리
  - 카카오 인증 토큰 유효성 검증

  [처리 결과]
  - 성공 시
    - 회원 ID 발급, 접근 토큰 발급, 온보딩 화면 전환
  - 실패 시
    - 카카오 인증 실패: "인증에 실패했어요. 다시 시도해주세요" 안내
    - 네트워크 오류: "인터넷 연결을 확인해주세요" 안내

- M/5
```

```
UFR-MBR-020: [취향 온보딩 퀴즈] 사용자로서 | 나는, 첫날부터 쓸만한 추천을 받기 위해 | 3분 이내에 완료되는 취향 퀴즈를 진행하고 싶다.
Pain Point: 여정맵 2단계 — 선택지 과부하, 콜드스타트 문제

- 시나리오: 취향 퀴즈 완료
  회원가입 직후 온보딩 화면에 진입한 상황에서 | 음식 카드 10장을 좋아요/싫어요로 스와이프하면 | 초기 취향 프로파일이 생성되고 첫 추천을 받을 수 있다.

  [입력 요구사항]
  - 음식 카드 스와이프 결과: 최소 7장 이상 완료 필수
  - 각 카드: 좋아요/싫어요 이진 선택

  [검증 요구사항]
  - 최소 스와이프 수 검증: 7장 미만 시 "조금만 더!" 안내
  - 퀴즈 소요 시간: 3분 이내 완료 가능하도록 카드 수 제한
  - 진행률 표시: 현재 진행 상태 실시간 표시

  [처리 결과]
  - 성공 시
    - 초기 취향 벡터 생성, 선호 카테고리 Top 3 표시, "취향 프로파일 완성!" 축하 메시지
  - 실패 시
    - 중간 이탈: 진행 상태 저장, 재진입 시 이어서 진행
    - 스킵 선택: "나중에 하기" 허용, 콜드스타트 안전망 적용

- M/8
```

```
UFR-MBR-030: [위치 정보 동의] 사용자로서 | 나는, 주변 식당 추천을 받기 위해 | 위치 정보 제공에 동의하고 싶다.
Pain Point: 여정맵 2단계 — 위치 기반 탐색의 전제 조건

- 시나리오: 위치 정보 동의 처리
  온보딩 퀴즈 완료 후 위치 동의 화면에 진입한 상황에서 | 위치 정보 수집 목적과 보유 기간을 확인하고 동의하면 | 위치 기반 추천 기능이 활성화된다.

  [입력 요구사항]
  - 동의 여부: 동의/거절

  [검증 요구사항]
  - 위치정보법 준수: 수집 목적 고지, 보유 기간(6개월) 고지, 철회 방법 안내
  - OS 위치 권한과 앱 내 동의 이중 확인

  [처리 결과]
  - 성공 시
    - 위치 기반 추천 활성화, 현재 위치 자동 인식
  - 실패 시
    - 동의 거절: 수동 위치 입력 모드로 전환, "위치를 직접 입력해주세요" 안내

- M/3
```

```
UFR-MBR-040: [알레르기/식이제한 설정] 사용자로서 | 나는, 안전한 추천을 받기 위해 | 알레르기와 식이제한 정보를 설정하고 싶다.
Pain Point: 여정맵 3단계 — 식사 선택의 안전성 확보

- 시나리오: 식이제한 설정 완료
  온보딩 또는 프로필 설정 화면에서 | 알레르기 항목(땅콩, 갑각류 등)과 식이 유형(채식, 할랄 등)을 선택하면 | 해당 식재료 포함 식당이 추천에서 하드 필터링된다.

  [입력 요구사항]
  - 알레르기 항목: 다중 선택 (8대 알레르겐 + 직접 입력)
  - 식이 유형: 단일 선택 (일반/채식/비건/할랄/기타)

  [검증 요구사항]
  - 민감 정보 별도 동의: 건강 관련 정보 수집 동의 확인
  - 하드 필터 등록: 추천 시 해당 식재료 절대 제외
  - 페일세이프: 필터 적용 불확실 시 해당 식당 전체 제외

  [처리 결과]
  - 성공 시
    - 식이제한 필터 등록 완료, 등록된 제한 요약 표시
  - 실패 시
    - 스킵 허용: 선택 사항이므로 미설정 시 필터 없이 진행

- S/5
```

```
UFR-MBR-050: [프로필 조회 및 수정] 사용자로서 | 나는, 내 정보를 관리하기 위해 | 프로필 정보를 조회하고 수정하고 싶다.
Pain Point: 여정맵 6단계 — 루틴 관리, 설정 변경 필요

- 시나리오: 프로필 정보 수정
  프로필 화면에 진입한 상황에서 | 닉네임, 식이제한, 알림 설정 등을 수정하고 저장하면 | 변경된 정보가 즉시 반영되고 다음 추천부터 적용된다.

  [입력 요구사항]
  - 닉네임: 2~20자, 특수문자 제한
  - 식이제한: 변경 가능
  - 알림 설정: 추천 알림 ON/OFF, 피드백 리마인더 ON/OFF

  [처리 결과]
  - 성공 시
    - 프로필 업데이트 완료, "설정이 저장되었어요" 안내
  - 실패 시
    - 유효성 오류: 해당 필드 하이라이트 + 오류 메시지

- C/3
```

## 2. 추천·이력 서비스 (REC)

### 2) 오늘의 추천 조회

```
UFR-REC-010: [오늘의 추천 3개 조회] 사용자로서 | 나는, 탐색 없이 바로 결정하기 위해 | 앱을 열면 즉시 오늘의 추천 3개를 확인하고 싶다.
Pain Point: 여정맵 2단계 — 평균 13~18분 탐색, 선택지 과부하로 극도의 피로

- 시나리오: 오늘의 추천 정상 조회
  로그인 상태에서 앱 메인 화면에 진입한 상황에서 | 현재 위치와 시간이 자동 인식되면 | 개인화된 추천 3개가 카드 형태로 즉시 표시된다.

  [입력 요구사항]
  - 현재 위치: GPS 자동 인식 또는 수동 입력
  - 현재 시간: 자동 인식

  [검증 요구사항]
  - 컨텍스트 파라미터 수집: 최근 7일 식사 이력, 날씨, 요일/시간
  - 알레르기 하드 필터 적용: 식이제한 식재료 포함 식당 완전 제거
  - 반복 방지: 최근 3일 내 동일 식당 추천 제외
  - 추천 카드 포함 정보: 식당명, 대표 메뉴, 추천 이유 한 줄, 확신 스코어, 거리, 예상 소요시간
  - 응답 시간: 3초 이내

  [처리 결과]
  - 성공 시
    - 추천 3개 카드 표시, 추천 이유 한 줄 각각 표시
  - 실패 시
    - 위치 미확인: "위치를 설정해주세요" 안내 + 수동 입력 경로
    - API 오류: 캐시된 이전 추천 표시 + "최신 추천을 불러오고 있어요" 안내

- M/21
```

```
UFR-REC-020: [추천 이유 상세 확인] 사용자로서 | 나는, 추천을 신뢰하기 위해 | 왜 이 메뉴가 추천되었는지 상세 이유를 확인하고 싶다.
Pain Point: 여정맵 2단계 — 광고 섞인 신뢰 없는 리뷰, "나를 위한 추천인지 알 수 없다"

- 시나리오: 추천 근거 상세 조회
  추천 카드가 표시된 상황에서 | 추천 카드의 "왜?" 버튼을 탭하면 | 추천 근거 상세(A8: 확신 스코어 + 자연어 설명)가 표시된다.

  [입력 요구사항]
  - 추천 ID

  [검증 요구사항]
  - 추천 이유 자연어 설명: "비 오는 날 + 어제 양식 → 따뜻한 한식 추천" 형태
  - 확신 스코어: 상위 3개 추천의 확률(%) 표시
  - 반영된 컨텍스트 태그: 날씨, 이력, 취향 중 어떤 요소가 반영되었는지 표시

  [처리 결과]
  - 성공 시
    - 추천 근거 상세 화면 표시: 자연어 이유 + 확신 스코어 + 컨텍스트 태그
  - 실패 시
    - 설명 생성 실패: "추천 이유를 준비 중이에요" + 기본 추천 이유(거리/평점) 표시

- M/13
```

```
UFR-REC-030: [콜드스타트 안전망 추천] 시스템으로서 | 나는, 신규 사용자에게도 쓸만한 추천을 제공하기 위해 | 데이터 부족 시 직군 클러스터 기반 안전망 추천을 적용하고 싶다.
Pain Point: 여정맵 2단계 — 첫 사용자의 추천 품질 보장

- 시나리오: 콜드스타트 사용자 추천
  피드백 5건 미만 사용자가 추천을 요청한 상황에서 | 시스템이 데이터 부족을 감지하면 | 직군 클러스터 Bayesian Prior + 온보딩 데이터 기반 추천을 제공한다.

  [검증 요구사항]
  - 콜드스타트 감지: 누적 피드백 5건 미만
  - 안전망 적용: 직군 클러스터 Prior + 지역 인기 메뉴 가중치
  - 투명성: "아직 취향을 학습 중이에요" 안내 메시지 표시
  - 학습 독려: "3일만 더 기록하면 추천이 확 달라져요!" 메시지

  [처리 결과]
  - 성공 시
    - 안전망 추천 3개 표시 + 학습 중 안내
  - 실패 시
    - 최소 데이터도 없는 경우: 지역 인기 메뉴 Top 3 표시

- M/13
```

### 3) 추천 수락 및 식당 선택

```
UFR-REC-040: [추천 수락] 사용자로서 | 나는, 빠르게 결정을 완료하기 위해 | 마음에 드는 추천을 수락하고 싶다.
Pain Point: 여정맵 3단계 — 탐색 13~18분 후 기존 식당 회귀, 결정 후 불안

- 시나리오: 추천 수락 처리
  추천 3개가 표시된 상황에서 | 원하는 추천 카드의 "여기 갈래요" 버튼을 탭하면 | 수락이 기록되고 식당 안내 화면으로 전환된다.

  [검증 요구사항]
  - 수락 반응 시간 기록: 추천 표시부터 수락까지 시간 측정 (망설임/확신 구별 학습용)
  - 수락 이력 저장: 회원 ID, 추천 ID, 식당 ID, 수락 시간

  [처리 결과]
  - 성공 시
    - 수락 기록 완료, 식당 길찾기 화면 전환
  - 실패 시
    - 네트워크 오류: 오프라인 저장 후 재접속 시 동기화

- M/5
```

```
UFR-REC-050: [추천 거절 및 대체 추천] 사용자로서 | 나는, 맞지 않는 추천을 교체하기 위해 | 추천을 거절하고 새로운 대체 추천을 받고 싶다.
Pain Point: 여정맵 3단계 — 결정 후 "더 나은 곳이 있었을 것"이라는 불안
```
